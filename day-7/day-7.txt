TERRAFORM + GCP TRAINING
DAY 7 — COMPUTE ENGINE: VIRTUAL MACHINES

============================================================
1. WHAT SERVICE ARE WE USING?
============================================================

Google Compute Engine provides virtual machines (VMs) that run operating systems and applications on Google Cloud infrastructure.

Terraform resource:
google_compute_instance

A VM definition usually includes:
- Name, project, zone, and machine type.
- Boot disk and operating system image.
- Network interface and subnet.
- Optional metadata, startup script, labels, and service account.

============================================================
5. FILE: main.tf
============================================================

resource "google_compute_instance" "training" {
  name         = var.vm_name
  project      = var.project_id
  zone         = var.zone
  machine_type = var.machine_type

  boot_disk {
    initialize_params {
      image = "debian-cloud/debian-12"
      size  = var.boot_disk_size_gb
      type  = "pd-balanced"
    }
  }

  network_interface {
    subnetwork = var.subnetwork
  }

  metadata = {
    enable-oslogin = "TRUE"
  }

  labels = {
    environment = "training"
    managed_by  = "terraform"
  }
}

Resource component explanations:
- name: VM name shown in Compute Engine.
- project: project where the VM is created.
- zone: specific zone where the VM runs.
- machine_type: determines the VM's vCPU and memory configuration.
- boot_disk: defines the operating system disk.
- initialize_params.image: operating system image used to create the boot disk.
- size: boot disk capacity in GB.
- type: persistent disk performance/cost type.
- network_interface: connects the VM to a subnet.
- metadata: passes VM metadata settings; enable-oslogin enables OS Login integration.
- labels: searchable key-value metadata for resource organization and billing analysis.

This configuration does not include access_config {}, so it does not request an external IPv4 address. Use an approved private access method such as IAP or a bastion, or intentionally configure an external IP if the lab requires it.

Optional startup script example:
metadata_startup_script = <<-EOT
  #!/bin/bash
  apt-get update
  apt-get install -y nginx
  systemctl enable --now nginx
EOT

Add this argument inside the VM resource only if you want to demonstrate startup scripts. Confirm outbound access and package repositories are available.

7. TERRAFORM WORKFLOW
============================================================

Enable the Compute Engine API and authenticate with an approved method, for example:
gcloud auth application-default login

Run:
terraform init
terraform fmt
terraform validate
terraform plan
terraform apply
terraform output

Review the plan before applying. Destroy lab resources when no longer needed:
terraform destroy

============================================================
9. KEY TAKEAWAYS
============================================================

- google_compute_instance provisions a Compute Engine VM.
- Machine type determines compute capacity.
- Boot disk settings define the OS disk.
- Network interface attaches the VM to a subnet.
- A firewall rule does not assign an external IP.
- Outputs expose useful attributes after apply.
