* GCP project available
* Billing enabled

```text

GCP APIs
      |
      v
GCS
```

# 3. Terraform Project Structure

```text
gcs-training/
│
├── providers.tf
├── variables.tf
├── terraform.tfvars
├── main.tf
└── outputs.tf
```

### File Purpose

| File               | Purpose                  |
| ------------------ | ------------------------ |
| `providers.tf`     | Provider configuration   |
| `variables.tf`     | Variable declarations    |
| `terraform.tfvars` | Variable values          |
| `main.tf`          | Infrastructure resources |
| `outputs.tf`       | Output values            |

Terraform automatically loads `.tf` files from the same directory.

---

# 4. Google Provider

### providers.tf

```hcl
terraform {
  required_providers {
    google = {
      source  = "hashicorp/google"
      version = "~> 7.0"
    }
  }
}

provider "google" {
  project = var.project_id
  region  = var.region
}
```

### Provider

* Connects Terraform to GCP
* Communicates with GCP APIs
* Uses configured authentication
* Uses the specified GCP project

# 6. Variables

### variables.tf

```hcl
variable "project_id" {
  type        = string
  description = "GCP Project ID"
}

variable "region" {
  type        = string
  description = "GCP region"
  default     = "asia-south1"
}

variable "bucket_name" {
  type        = string
  description = "GCS bucket name"
}
```

Variables make the configuration reusable and avoid hardcoding values.

Example:

```hcl
project = var.project_id
```

instead of:

```hcl
project = "my-project-123"
```

# 8. Enable Cloud Storage API

The Cloud Storage API can also be managed through Terraform.

Add to `main.tf`:

```hcl
resource "google_project_service" "storage_api" {
  project = var.project_id
  service = "storage.googleapis.com"

  disable_on_destroy = false
}
```

This enables:

```text
Cloud Storage API
storage.googleapis.com
```

Terraform will manage the API as a resource.

---

# 9. Google Cloud Storage

Google Cloud Storage (GCS) is an object storage service.

Basic structure:

```text
GCP Project
     |
     v
   Bucket
     |
     v
   Objects
```

### Bucket

A bucket is a container used to store objects.

### Object

An object is a file stored inside a bucket.

Example:

```text
Bucket: application-backup

Objects:
├── database.sql
├── application.zip
└── logs/app.log
```

---

# 10. Create GCS Bucket

### main.tf

```hcl
resource "google_storage_bucket" "training" {
  name                        = var.bucket_name
  location                    = var.region
  uniform_bucket_level_access = true
  force_destroy               = false

  labels = {
    environment = "dev"
    managed_by  = "terraform"
    purpose     = "training"
  }

  depends_on = [
    google_project_service.storage_api
  ]
}
```

### Resource Syntax

```hcl
resource "RESOURCE_TYPE" "RESOURCE_NAME" {
  ...
}
```

Example:

```hcl
resource "google_storage_bucket" "training"
```

`google_storage_bucket`

* Terraform resource type

`training`

* Terraform resource name

Reference:

```hcl
google_storage_bucket.training
```

---

# 11. Resource Dependency

The bucket contains:

```hcl
depends_on = [
  google_project_service.storage_api
]
```

This creates the dependency:

```text
Enable Cloud Storage API
          |
          v
    Create GCS Bucket
```

Terraform will enable the API before creating the bucket.

The explicit dependency is useful here because the bucket requires the API to be enabled.

# 18. Uniform Bucket-Level Access

```hcl
uniform_bucket_level_access = true
```

This enables IAM-based access control at the bucket level.

Benefits:

* Centralized access management
* Consistent IAM permissions
* Simplified bucket access control
* Avoids relying on object ACLs

---

# 19. Force Destroy

```hcl
force_destroy = false
```

When `false`:

* Terraform will not automatically delete objects when destroying a non-empty bucket.

When `true`:

* Terraform can delete objects as part of bucket destruction.

Example:

```hcl
force_destroy = true
```

Use carefully because it can result in data deletion.
